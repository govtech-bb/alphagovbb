# Unit test coverage in checks

Added Vitest coverage reporting to the `check` pipeline as an informational
signal — visible on every run, not gating.

## Why

The repo had two compute modules under unit test (`severance/compute.ts`,
`pension/compute.ts`) but no way to see what coverage looked like. Without a
number on the screen, there's no pressure (or even data) to grow the unit
suite as the codebase grows.

## What now exists

Running `./check.sh` prints:

```
[ OK ] vitest       4s
[INFO] coverage      9.2% stmts  8.9% branches  3.9% funcs  9.5% lines
[ OK ] typecheck    5s
[ OK ] eslint       …
[ OK ] prettier     …
```

The baseline today is ~9% of `apps/web/src/**`. That number reflects current
reality: only the two calculator compute modules are covered. Everything
else (routes, libs, components) is uncovered.

## Decisions worth keeping in mind

- **No thresholds.** Coverage is intentionally never a pass/fail gate.
  Pass/fail in `run-checks.sh` is reserved for correctness (tests,
  typecheck) and consistency (lint, format). The `[INFO]` prefix
  distinguishes informational signals from gating ones in the output.
- **V8 provider, not Istanbul.** Vitest's default; faster, no Babel
  transform pass. For pure-function compute modules the branch-coverage
  difference vs Istanbul is negligible.
- **Always run, even for local `./check.sh`.** Coverage adds ~1s to the
  vitest run; cheap enough that having the number every time is worth
  more than the saved second. Local `pnpm test` (without `./check.sh`)
  still runs cover-free for tight iteration.
- **`text-summary` + `json-summary` reporters only.** No HTML report
  generated by default — keeps the build artefact lean. Devs who want
  per-file detail can add `--coverage.reporter=html` ad-hoc.
- **Helper function in `run-checks.sh` parses `coverage-summary.json`
  with `node -e`**, not `jq`, because the check container is the deps
  image (Node, no jq). Failures in extraction are swallowed so a broken
  summary file can never fail the check.

## Out of scope

- Coverage from the Playwright e2e suite. Playwright has its own coverage
  story (`monocart-reporter` or istanbul-middleware) which is non-trivial
  to wire and not what was asked for. The number here reflects unit
  coverage only.
- Coverage thresholds / minimums. If/when the suite is meaningfully
  larger, we can revisit gating on a floor — but that would be a
  reversal of the "informational only" stance, so it deserves its own
  discussion.
